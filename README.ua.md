## 🛠️ Встановлення

### Варіант 1: Швидкий запуск через готовий Docker-образ (Рекомендовано)

Запуск n8n Backup Manager за допомогою офіційного мультиплатформеного образу з GitHub Container Registry (`ghcr.io/aleksnero/n8n-backup-manager`) без необхідності локального збирання залежностей:

```bash
# 1. Завантажте docker-compose.yml
curl -O https://raw.githubusercontent.com/aleksnero/n8n-backup-manager/main/docker-compose.yml

# 2. Завантажте образ та запустіть контейнер
docker compose pull && docker compose up -d
```

---

### Варіант 2: Завантаження релізного архіву

```bash
# 1. Завантажте та розпакуйте реліз

unzip release.zip
cd n8n-backup-manager

docker compose up -d
```

## 📖 Використання

### Налаштування підключення

Перейдіть у розділ **Settings** та вкажіть:

**Для Docker:**
- **n8n Container Name**: назва контейнера з n8n
- **Database Container Name**: назва контейнера з БД (наприклад, `postgres-1`)
- **Database Type**: PostgreSQL або SQLite

**Для PostgreSQL:**
- **Database User**: ім'я користувача
- **Database Password**: пароль
- **Database Name**: назва бази даних

**Для SQLite:**
- **Database Path**: шлях до файлу БД (наприклад, `/home/node/.n8n/database.sqlite`)

**Оптимізація бекапів:**
- **Стиснення (Gzip)**: зменшує розмір файлів
- **Шифрування (AES-256)**: захист даних паролем

---

### Хмарні налаштування

Перейдіть у **Settings → Cloud** і оберіть провайдера:

| Провайдер | Необхідні поля |
|---|---|
| **S3 Compatible** | Endpoint, Region, Bucket, Access Key, Secret Key |
| **Google Drive** | Client ID, Client Secret, Refresh Token, Folder ID *(необов'язково)* |
| **Microsoft OneDrive** | Client ID, Client Secret, Refresh Token |

**Отримання ключів Google Drive:**
1. Відкрийте [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Credentials
2. Створіть **OAuth 2.0 Client ID** (тип: Desktop app)
3. Використайте [Google OAuth Playground](https://developers.google.com/oauthplayground) зі scope `https://www.googleapis.com/auth/drive.file` для отримання **Refresh Token**

**Отримання ключів OneDrive:**
1. Відкрийте [Azure Portal](https://portal.azure.com/) → App registrations → New registration
2. Додайте `Files.ReadWrite` у розділі Microsoft Graph API permissions
3. Використайте [Microsoft Graph Explorer](https://developer.microsoft.com/en-us/graph/graph-explorer) для генерації **Refresh Token**

> [!TIP]
> **[Дивіться Детальну інструкцію з налаштування хмари](CLOUD_SETUP.ua.md)** для покрокових вказівок.

### Перевірка цілісності бекапу *(тільки Linux)*

Переконайтесь, що бекап не пошкоджений перед його відновленням.

1. Перейдіть у **Backups**.
2. Натисніть на **іконку щита** біля будь-якого бекапу.
3. Система виконає команду `tar --list` (для `.tar.gz`) або валідацію розміру (для `.sql`).
4. Результат: ✅ Гаразд / ❌ Пошкоджено / ⚠️ Тільки Linux

> [!NOTE]
> Ця функція доступна лише на Linux. На Windows/macOS ця кнопка не відображається.

### Семантична верифікація цілісності *(Нове в v1.6.0)*

Окрім простих перевірок на рівні файлу, система виконує **глибокий семантичний аналіз** кожного бекапу:

- **Підрахунок сутностей** — перевіряє, що робочі процеси та облікові дані реально існують у файлі бекапу
- **Евристика свіжості (Freshness Heuristic)** — перевіряє, коли востаннє редагувався будь-який робочий процес; якщо всі дані старіші за 30 днів (можна налаштувати), з'являється ⚠️ попередження. Це виявляє ситуації, коли бекапи знімаються зі старої або покинутої бази після міграції
- **Захист від аномальних змін (Delta Anomaly Guard)** — порівнює кількість сутностей у поточному бекапі з попереднім. Якщо кількість робочих процесів або облікових даних впала більш ніж на 30% (можна налаштувати), з'являється ⚠️ попередження. Це виявляє випадкову втрату даних або проблеми з правами при експорті

Результати відображаються як багатостатусний бейдж на Dashboard:

| Бейдж | Значення |
|:---:|---|
| ✅ **OK** | Бекап перевірений, дані свіжі та кількість стабільна |
| ⚠️ **Попередження** | Бекап структурно валідний, але евристики виявили можливі проблеми |
| ❌ **Пошкоджено** | Бекап не вдалося розшифрувати, розпакувати, або він містить нуль сутностей |

> [!TIP]
> Пороги можна налаштувати в **Settings**: `integrity_staleness_days` (за замовчуванням: 30) та `integrity_drop_percent` (за замовчуванням: 30).

## 📷 Снапшоти робочих процесів та облікових даних

Снапшоти робочих процесів — це **гранулярна система резервного копіювання**, яка працює паралельно з повними бекапами бази даних. Замість того, щоб копіювати всю базу, снапшоти зберігають **окремі робочі процеси та пов'язані з ними облікові дані**, що дозволяє точно відкотити один процес, не зачіпаючи решту вашого n8n.

### Що зберігається у снапшоті

Кожен снапшот містить:
- **Визначення робочого процесу** (назва, вузли, з'єднання, налаштування, статичні дані)
- **Всі облікові дані**, що використовуються цим процесом (зашифровані)
- **Метадані** (дата створення, тип, нотатки)

Все упаковується у `.zip` архів і за бажанням шифрується тим же ключем AES-256, що використовується для повних бекапів.

### Коли використовувати снапшоти vs повні бекапи

| Сценарій | Використовуйте |
|---|---|
| Захист від повної втрати бази даних | **Повний бекап** |
| Відкат конкретного зламаного процесу | **Снапшот** |
| Збереження робочої версії перед редагуванням | **Снапшот** |
| Міграція процесу на інший n8n | **Снапшот** (завантажити і відновити) |
| Плановий щоденний/тижневий захист | **Обидва** (розклад бекапів + розклад снапшотів) |

### Створення снапшоту

**Вручну:**
1. Перейдіть у розділ **Workflow & Credentials Snapshots** у бічній панелі.
2. Ви побачите живий список усіх робочих процесів вашого n8n.
3. Натисніть **іконку камери** 📸 біля потрібного процесу.
4. За бажанням додайте **нотатку**, що описує цю версію.
5. Снапшот створюється миттєво.

**Автоматично:**
1. Перейдіть у **Settings → Workflow Snapshots**.
2. Увімкніть перемикач **Auto-Schedule**.
3. Оберіть **розклад** (інтервал у хвилинах або cron-вираз).
4. Оберіть **область дії**:
   - **All Active** — снапшоти всіх активних процесів
   - **All** — снапшоти всіх процесів (включно з неактивними)
5. Встановіть **кількість збережень** (скільки снапшотів зберігати на процес; захищені снапшоти виключаються з ротації).

### Відновлення зі снапшоту

1. Перейдіть у **Workflow & Credentials Snapshots**.
2. Знайдіть потрібний снапшот у таблиці.
3. Натисніть **іконку відновлення** ↩️.
4. Підтвердіть дію.
5. Система **перезапише робочий процес та його облікові дані** в живій базі n8n. n8n підхоплює зміни автоматично — перезапуск не потрібен.

> [!IMPORTANT]
> Відновлення снапшоту **замінює** поточну версію цього процесу та його облікових даних у живій базі. Інші процеси не зачіпаються.

### Захист та завантаження снапшотів

- **Захист**: Натисніть **іконку замка** 🔒, щоб запобігти автоматичному видаленню снапшоту при ротації.
- **Завантаження**: Натисніть **іконку завантаження** ⬇️, щоб експортувати снапшот як `.zip` архів на ваш комп'ютер.
- **Видалення**: Натисніть **іконку кошика** 🗑️, щоб видалити снапшот назавжди.

### Віджет на Dashboard

На Dashboard відображається картка **Workflow Snapshots** з інформацією:
- Загальна кількість робочих процесів у вашому n8n
- Загальна кількість збережених снапшотів
- Таймер зворотного відліку до наступного автоматичного снапшоту (коли планування увімкнено)

## 📰 Стрічка новин

На Dashboard є **стрічка новин**, яка показує анонси, поради та важливі повідомлення від розробника — без необхідності оновлювати додаток.

- Новини завантажуються з файлу `news.json` проєкту на GitHub
- Ви можете **відхилити** окремі новини кнопкою ✕
- Ви можете **позначити як прочитане**, щоб зупинити індикатор

**Щоб повністю вимкнути стрічку новин:**
1. Перейдіть у **Settings → General**.
2. Вимкніть перемикач **News Feed**.
3. Dashboard більше не буде завантажувати та відображати новини.

> [!NOTE]
> Стрічка новин — це **односторонній канал читання**. Вона не надсилає жодних даних з вашого екземпляру. Додаток лише завантажує публічний JSON-файл.

## 🔄 Система оновлень

Backup Manager підтримує автоматичне оновлення з GitHub:

1. Перейдіть у розділ **Updates** → **Check for Updates**
2. Якщо доступна нова версія, ви побачите інформацію про реліз
3. Натисніть **Apply Update** → Підтвердіть
4. Система: створить бекап → завантажить оновлення → застосує → перезапуститься

### Rollback (Відкат)

Якщо після оновлення виникли проблеми:
1. Перейдіть у розділ **Updates**
2. Натисніть **Rollback**
3. Система відновить попередню версію

## 🐳 Docker Compose

Приклад `docker-compose.yml`:

```yaml
services:
  backup-manager:
    build: .
    container_name: n8n-backup-manager
    restart: unless-stopped
    ports:
      - "${PORT:-3000}:${PORT:-3000}"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - ./backups:/app/backups
      - ./data:/app/data
    environment:
      - PORT=${PORT:-3000}
      - JWT_SECRET=${JWT_SECRET:-change_this_secret}
    networks:
      - default
      - npm_public

networks:
  npm_public:
    external: true
    name: nginx_proxy_manager_default
```

## 🔧 Налаштування

### Змінні середовища

| Змінна | Опис | За замовчуванням |
|--------|------|------------------|
| `JWT_SECRET` | Секретний ключ для JWT токенів | `secret-key` |
| `UPDATE_SERVER_URL` | URL для перевірки оновлень | GitHub URL |
| `PORT` | Порт сервера | `3000` |

### Volumes

| Volume | Опис |
|--------|------|
| `/var/run/docker.sock` | Доступ до Docker для управління контейнерами |
| `./backups` | Зберігання резервних копій (повні бекапи + снапшоти) |
| `./data` | База даних SQLite |
